### 2. El proceso de conexión y extracción

El procedimiento siempre sigue tres pasos:

1. **Crear el motor:** Establecer las credenciales de acceso.
2. **Ejecutar la consulta (Query):** Escribir SQL para traer solo los datos que necesitas.
3. **Cargar en Pandas:** Convertir el resultado a formato tabular.

```python
import pandas as pd
from sqlalchemy import create_engine

# 1. Configuración de conexión (Credenciales)
# Formato: dialecto+driver://usuario:password@host:puerto/nombre_base_de_datos
db_connection_str = 'postgresql+psycopg2://usuario:contraseña@localhost:5432/mi_base_de_datos'
db_connection = create_engine(db_connection_str)

# 2. Definir la consulta SQL
# Recomendación: No hagas 'SELECT *', trae solo las columnas necesarias para el modelo
query = """
SELECT id, edad, glucosa, presion 
FROM pacientes 
WHERE edad > 50
"""


# 3. Extracción directa a un DataFrame de Pandas
# Caso de estudio adaptado
df = pd.read_sql(query, db_connection)

query = """
SELECT id, edad, glucosa, presion 
FROM pacientes 
WHERE edad > 50
"""

df1 = pd.read_sql(query, db_engine1) # PostgreSQL
df2 = pd.read_sql(query, db_engine2) # MySQL/MARIADB

print(df.head())

### 3. Buenas prácticas para IA

Cuando extraes datos desde una base de datos para alimentar un modelo, ten en cuenta lo siguiente:

* **Filtrado en el servidor:** No traigas toda la tabla a tu memoria RAM si no es necesario. Filtra por fechas, categorías o usuarios directamente en la consulta SQL (`WHERE`, `GROUP BY`).
* **Manejo de Memoria:** Si la base de datos es gigantesca (millones de filas), usa el parámetro `chunksize` en `read_sql` para procesar los datos por lotes y no saturar la memoria de tu computadora.
* **Seguridad:** Nunca escribas contraseñas directamente en tu código (como en el ejemplo de arriba). Utiliza **variables de entorno** (`os.environ.get('DB_PASSWORD')`) para mantener tus credenciales protegidas.

--- Ejemplos de buenas practicas ---
Aquí tienes ejemplos prácticos para implementar estas buenas prácticas en tu flujo de trabajo de Ciencia de Datos:

### 1. Filtrado en el servidor

No traigas toda la tabla a tu memoria RAM si no es necesario. Filtra por fechas, categorías o usuarios directamente en la consulta SQL usando `WHERE` o `GROUP BY`.

* **Incorrecto (Carga todo):**
```python
# Carga millones de filas innecesariamente
df = pd.read_sql("SELECT * FROM pacientes", db_engine1)

```

* **Correcto (Filtro eficiente):**
```python
# Filtra desde el servidor antes de traer los datos a Python
query = """
SELECT id, edad, glucosa 
FROM pacientes 
WHERE edad >= 50 AND estado_salud = 'Enfermo'
"""
df1 = pd.read_sql(query, db_engine1)

```

### 2. Manejo de Memoria

Si la base de datos es gigantesca (millones de filas), usa el parámetro `chunksize` en `read_sql` para procesar los datos por lotes y no saturar la memoria de tu computadora.

* **Ejemplo de procesamiento por bloques:**
```python
query = "SELECT * FROM pacientes"

# Procesa bloques de 25 registros a la vez
query = "SELECT * FROM pacientes"
resultado_parcial = []
for chunk in pd.read_sql(query, db_engine1, chunksize=25):
    # Realiza transformaciones o cálculos por cada bloque
    resultado_parcial_tmp = chunk.groupby('estado_salud')['edad'].mean()
    resultado_parcial.append(resultado_parcial_tmp)
    print(f"Procesado bloque de {len(chunk)} filas.")

print(resultado_parcial)

### 3. Seguridad

Nunca escribas contraseñas directamente en tu código. Utiliza **variables de entorno** (`os.environ.get('DB_PASSWORD')`) para mantener tus credenciales protegidas.

* **Ejemplo seguro usando `os.environ`:**
```python
import os
from sqlalchemy import create_engine

# Recupera la contraseña desde una variable de entorno configurada en tu sistema
db_pass = os.environ.get('DB_PASSWORD')

# Construye la cadena de conexión dinámicamente
connection_str = f'postgresql+psycopg2://usuario:{db_pass}@localhost:5432/bd_prueba'
db_engine = create_engine(connection_str)

```

Consideraciones, respecto a la definición de variables:
////////////////////////////////////////////////////////

Para definir una variable de entorno en Windows de manera que sea accesible por `os.environ.get('DB_PASSWORD')` en Python, tienes dos formas principales: una permanente (a través de la configuración del sistema) y una temporal (a través de la terminal).

### 1. Opción Permanente (Recomendada)

Esta opción hace que la variable esté disponible en cualquier terminal o IDE que abras en el futuro.

1. Presiona la tecla **Windows** y escribe: **"Editar las variables de entorno del sistema"**.
2. Haz clic en el botón que dice **Variables de entorno...** en la parte inferior de la ventana.
3. En la sección **Variables de usuario** (la parte superior), haz clic en el botón **Nueva...**.
4. En "Nombre de la variable", escribe: `DB_PASSWORD`.
5. En "Valor de la variable", escribe tu contraseña (ej. `1234567`).
6. Haz clic en **Aceptar** en todas las ventanas para guardar los cambios.

**Importante:** Debes cerrar y volver a abrir tu terminal (CMD, PowerShell o VS Code) para que reconozcan el cambio, ya que las variables de entorno se cargan al iniciar el proceso de la terminal.

---

### 2. Opción Temporal (Para pruebas rápidas)

Si solo quieres probar el código sin modificar la configuración global del sistema, puedes definirla en la misma terminal donde vas a ejecutar tu script de Python.

* **Si usas PowerShell:**
```powershell
$env:DB_PASSWORD = "1234567"
python tu_script.py

```

* **Si usas el Símbolo del sistema (CMD):**
```cmd
set DB_PASSWORD=1234567
python tu_script.py

```
Nota: Si se está utilizando el IDLE, la activación de dicho entorno, debe efectuarse
desde la misma terminal, donde se declaró la variable temporal.

### 4. ¿Por qué es diferente al CSV?

| Característica | Archivo CSV | Base de Datos (SQL) |
| --- | --- | --- |
| **Acceso** | Estático, local | Dinámico, concurrente |
| **Integridad** | Baja (fácil de modificar accidentalmente) | Alta (reglas y tipos de datos estrictos) |
| **Volumen** | Limitado por memoria | Casi ilimitado |
| **IA** | Útil para prototipos | Esencial para producción |

### Resumen del flujo para IA

1. **Conexión:** `SQLAlchemy` conecta el servidor con tu entorno.
2. **Consulta:** SQL selecciona las variables (`X`) y la etiqueta (`y`) necesarias.
3. **Conversión:** `pd.read_sql` transforma el resultado en un *DataFrame*.
4. **EDA/Modelado:** Aplicas el Análisis Exploratorio y el entrenamiento que ya conocemos.

**Consejo:** Antes de lanzar una consulta pesada en una base de datos de producción, siempre pruébala con un `LIMIT 10` al final. Así confirmarás que la sintaxis es correcta y que los nombres de las columnas son los que esperabas, sin arriesgarte a bloquear el servidor con una consulta masiva innecesaria.
