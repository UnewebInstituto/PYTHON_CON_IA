### Paso 2: Tarea:

1. **Limpie los datos:** Elimine `id` y transforme columnas como `sex` (Male/Female) y `cp` (chest pain) a formato numérico sin que el modelo falle.
2. **Valide:** Aplique la **Validación Cruzada Estratificada** para garantizar que los resultados no sean fruto del azar.
3. **Genere la Matriz de Confusión:** Que es la que nos dirá si estamos fallando al detectar pacientes enfermos.

Nota:
La columna **`num`** es tu variable objetivo (target)

En este dataset clínico, "num" representa la presencia y severidad de la enfermedad cardíaca en el paciente.

Es el atributo objetivo (target) que el modelo debe predecir. Tradicionalmente, en la base de datos de Cleveland (de donde proviene gran parte de esta información), el valor de num se codifica de la siguiente manera:

0: Ausencia de enfermedad cardíaca (Paciente sano).

1, 2, 3, 4: Presencia de enfermedad cardíaca, donde el número indica el grado de severidad o el número de vasos sanguíneos principales con estenosis (estrechamiento) significativa.

¿Por qué es importante para tu evaluación?
Es una variable de clasificación: Al tener valores discretos (0, 1, 2, 3, 4), el modelo lo trata como una clasificación multiclase.

Preparación para tu modelo: Si tu objetivo es simplemente detectar si el paciente está "enfermo" o "sano" (clasificación binaria), es muy común simplificar esta columna antes de entrenar, transformándola en 0 (sano) y 1 (cualquier valor de 1 a 4).


Script optimizado. Se  incluyó una limpieza robusta que maneja los nulos automáticamente (imputando la mediana para números y la moda para texto) y transforma todas las variables de texto a numéricas mediante `get_dummies`.

```python
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import StratifiedKFold, cross_val_predict
from sklearn.metrics import classification_report, confusion_matrix

# 1. Carga
df = pd.read_csv('heart_disease_uci.csv')

# 2. Limpieza de datos
df = df.drop('id', axis=1) # Eliminamos id

# Imputación de valores faltantes
for col in df.columns:
    if df[col].dtype in ['float64', 'int64']:
        df[col] = df[col].fillna(df[col].median())
    else:
        df[col] = df[col].fillna(df[col].mode()[0])

# 3. Transformación de categóricas a numéricas
# Esto convierte 'sex', 'cp', etc., en columnas binarias (0/1)
df_encoded = pd.get_dummies(df, drop_first=True)

# 4. Definición de variables
# 'num' es nuestra variable objetivo
X = df_encoded.drop('num', axis=1)
y = df_encoded['num']

# 5. Validación Cruzada Estratificada y Entrenamiento
modelo = RandomForestClassifier(n_estimators=100, random_state=42)
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

# Predicciones mediante validación cruzada
y_pred = cross_val_predict(modelo, X, y, cv=skf)

# 6. Reporte de Evaluación
print("--- Reporte de Clasificación Clínica ---")
print(classification_report(y, y_pred))

# 7. Matriz de Confusión
cm = confusion_matrix(y, y_pred)
plt.figure(figsize=(7, 5))
sns.heatmap(cm, annot=True, fmt='d', cmap='Greens')
plt.title("Matriz de Confusión - Diagnóstico Cardíaco")
plt.xlabel("Predicción")
plt.ylabel("Realidad")
plt.show()

```

### ¿Por qué este script garantiza el éxito?

* **Manejo de Nulos:** Al usar `fillna()` con la mediana y la moda, evitamos que los valores faltantes (como en `ca` o `slope`) rompan el modelo. Esto es crucial en datasets médicos donde la falta de un dato no significa necesariamente que el paciente no tenga la condición .
* **Transformación Total:** `pd.get_dummies` se encarga de convertir todas las columnas de texto (como `sex` y `cp`) automáticamente, permitiendo que el bosque aleatorio pueda realizar sus cálculos sin lanzar el error de conversión de texto a *float* .
* **Validación Cruzada Estratificada:** Al usar `StratifiedKFold`, nos aseguramos de que el modelo evalúe la capacidad de detección basándose en una muestra representativa de todos los estados clínicos presentes en los 920 registros.

**Siguiente paso:** Observa el `classification_report`. Si el **Recall** en las clases donde `num > 0` es bajo, significa que estamos perdiendo pacientes enfermos.

Para evaluar un modelo de **Churn** (fuga de clientes), como el que propone el dataset de *Telco Customer Churn* de Kaggle, no basta con saber si el modelo "acierta mucho". Necesitamos entender *dónde* se equivoca, porque en este negocio, un error puede costarte un cliente valioso.

Aquí te explico cómo aplicar estas herramientas de evaluación con el rigor que requiere un problema de retención.

### 1. La Matriz de Confusión: El mapa de tus errores

En lugar de una sola cifra, esta matriz desglosa los resultados en cuatro cuadrantes. Para Telco Churn, es vital entender la diferencia:

* **Verdaderos Positivos (TP):** Clientes que iban a irse y el modelo predijo correctamente que se irían. (¡Victoria!)
* **Verdaderos Negativos (TN):** Clientes que se quedarían y el modelo predijo que se quedarían.
* **Falsos Positivos (FP):** Clientes que el modelo marcó como "en riesgo de fuga", pero en realidad estaban felices. *Impacto:* Gastas dinero innecesario en campañas de retención.
* **Falsos Negativos (FN):** Clientes que se iban a ir, pero el modelo no lo detectó. *Impacto:* **El más peligroso.** Perdiste al cliente sin intentar retenerlo.

### 2. Precisión y Recall: ¿Qué pesa más?

* **Recall (Sensibilidad):** Mide qué porcentaje de los que realmente se fueron logramos detectar. **En Churn, esta suele ser nuestra prioridad número uno.** Queremos capturar a tantos "fugitivos" como sea posible, aunque eso implique equivocarnos con algunos clientes felices (Falsos Positivos).
* **Precisión:** Mide qué porcentaje de los que marcamos como "en riesgo" realmente se iban. Es útil para no malgastar el presupuesto de marketing en clientes que no necesitaban incentivos.

### 3. F1-Score: El equilibrio necesario

Como el dataset de Telco Churn suele estar desbalanceado (hay muchos más clientes que se quedan que los que se van), la "exactitud" (*accuracy*) clásica te mentirá. Si el 80% de tus clientes se quedan, un modelo que siempre predice "se quedan" tendrá un 80% de aciertos, pero será inútil.
**El F1-Score es tu salvavidas**, ya que combina Precisión y Recall en una sola métrica equilibrada.

### 4. Validación Cruzada (Stratified K-Fold)

Ya mencionamos esta técnica anteriormente, pero es crítica aquí. Dado que los clientes que abandonan son una minoría, un reparto aleatorio simple podría dejarte una división de entrenamiento sin *ningún* cliente fugado.

* **Stratified:** Asegura que en cada una de tus 5 rondas de evaluación, la proporción de clientes que se van (el "churn") sea idéntica a la del dataset original.
* **Resultado:** Obtienes una estimación mucho más honesta de cómo funcionará el modelo con clientes reales que nunca ha visto.

Para preparar tu dataset de *Telco Customer Churn* y obtener una matriz de confusión profesional, debemos ejecutar un pipeline completo: limpieza, codificación y evaluación.

Aquí tienes el código listo para ser ejecutado en tu entorno:

```python
import pandas as pd
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import confusion_matrix, classification_report
import seaborn as sns
import matplotlib.pyplot as plt

# 1. Carga y Limpieza Robusta
df = pd.read_csv('./WA_Fn-UseC_-Telco-Customer-Churn.csv')

# Conversión segura para evitar errores de asignación
df['TotalCharges'] = pd.to_numeric(df['TotalCharges'], errors='coerce').fillna(0)
df = df.drop('customerID', axis=1)

# 2. Codificación (Preparación para el Modelo)
# Convertimos todas las variables categóricas de una forma más limpia
# Esto soluciona el ValueError al convertir automáticamente todo a numérico
df = pd.get_dummies(df, drop_first=True)

# 3. Preparación de variables (asegurando el nombre correcto tras get_dummies)
# Al usar get_dummies, 'Churn_Yes' es el nuevo nombre de la columna target
X = df.drop('Churn_Yes', axis=1)
y = df['Churn_Yes']

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, stratify=y, random_state=42)

# 4. Entrenamiento
modelo = RandomForestClassifier(n_estimators=100, random_state=42)
modelo.fit(X_train, y_train)

# 5. Predicción y Evaluación
y_pred = modelo.predict(X_test)

# Visualización
cm = confusion_matrix(y_test, y_pred)
plt.figure(figsize=(8, 6))
sns.heatmap(cm, annot=True, fmt='d', cmap='Blues', 
            xticklabels=['No Churn', 'Churn'], 
            yticklabels=['No Churn', 'Churn'])
plt.ylabel('Real')
plt.xlabel('Predicho')
plt.title('Matriz de Confusión - Retención de Clientes')
plt.show()

print(classification_report(y_test, y_pred))
```

### Notas estratégicas para tu análisis:

* **`drop('customerID')`**: Es fundamental eliminar identificadores únicos, ya que de lo contrario el modelo "memorizará" los nombres (o IDs) y no aprenderá patrones reales de comportamiento.
* **`stratify=y`**: En el `train_test_split` es obligatorio. Garantiza que la proporción de clientes que se van (`Churn=1`) sea la misma en entrenamiento y en prueba.
* **Lectura de la matriz**:
* Fíjate en el cuadrante inferior izquierdo (Falsos Negativos). Ese es tu **dolor estratégico**: clientes que se fueron y no lograste identificar.
* Si los números en ese cuadrante son altos, significa que debes aplicar el ajuste del **umbral (threshold tuning)** que discutimos anteriormente (bajarlo de 0.5 a 0.3, por ejemplo).
