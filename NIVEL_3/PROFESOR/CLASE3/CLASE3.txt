La evaluación de modelos es la etapa crítica donde cuantificamos qué tan bien aprende nuestro algoritmo. No basta con que un modelo prediga; debemos saber si lo hace de forma confiable, equilibrada y generalizable.

---

### 1. Matriz de Confusión

Es una tabla que compara las predicciones de un modelo con los valores reales. Permite ver dónde se confunde el modelo.

Para una clasificación binaria, se compone de:

* **Verdaderos Positivos (VP):** El modelo predijo "positivo" y era correcto.
* **Verdaderos Negativos (VN):** El modelo predijo "negativo" y era correcto.
* **Falsos Positivos (FP - Error Tipo I):** El modelo predijo "positivo" incorrectamente (falsa alarma).
* **Falsos Negativos (FN - Error Tipo II):** El modelo predijo "negativo" incorrectamente (omisión grave).

---

### 2. Métricas de Rendimiento

Las métricas nos ayudan a interpretar la matriz de confusión con un número específico.

#### Precisión (Precision)

Responde: *¿De todos los casos que el modelo marcó como positivos, cuántos son realmente positivos?* 

* **Fórmula:** VP / (VP + FP)
* 
**Ejemplo:** En un sistema de detección de spam, una precisión alta significa que casi ningún correo importante fue marcado erróneamente como spam.


#### Recall (Sensibilidad o Exhaustividad)

Responde: *¿De todos los casos positivos que existen realmente, cuántos fue capaz de encontrar el modelo?* 

* **Fórmula:** VP / (VP + FN)
* 
**Ejemplo:** En un diagnóstico médico de una enfermedad grave, un recall alto es vital para asegurar que no se pase por alto ningún paciente enfermo.


---

### 3. Validación Cruzada (Cross-Validation)

Esta técnica evita que el modelo aprenda "de memoria" los datos de entrenamiento (sobreajuste o *overfitting*).

* **¿Cómo funciona?** El conjunto de datos se divide en K partes iguales (llamadas *folds*). El modelo se entrena K veces, usando una parte diferente para probar (test) en cada iteración y las otras para entrenar.
* **Ventaja:** Al final, promedias el desempeño de las K iteraciones, obteniendo una medida mucho más robusta y honesta de qué tan bien funcionará el modelo con datos nuevos que nunca ha visto.

---

### Ejemplo Integrador: Detección de Fraude

Imagina un modelo que detecta transacciones fraudulentas:

1. **Matriz de Confusión:** Si el modelo tiene muchos **Falsos Negativos (FN)**, el banco está dejando pasar transacciones fraudulentas, lo cual es muy peligroso.
2. **Recall:** Aquí el banco priorizará un **Recall alto** para atrapar la mayor cantidad posible de fraudes, aunque eso signifique ocasionalmente bloquear una transacción legítima (baja precisión).
3. **Validación Cruzada:** Si aplicas Validación Cruzada de 5 partes (K=5), te aseguras de que el modelo detecte fraudes en diferentes épocas o segmentos de tus datos de entrenamiento, confirmando que la detección no sea casualidad.

// BEGIN TITANIC CODE 

import pandas as pd
import numpy as np
from sklearn.model_selection import StratifiedKFold, cross_val_predict
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import confusion_matrix, classification_report, accuracy_score
import seaborn as sns
import matplotlib.pyplot as plt

# 1. Carga y Preprocesamiento básico (Necesario para el Titanic)
df = pd.read_csv('./NIVEL_3/PROFESOR/CLASE3/titanic_train.csv')
# Limpieza rápida: manejar nulos y convertir variables categóricas
df['Age'] = df['Age'].fillna(df['Age'].median())
df['Sex'] = df['Sex'].map({'male': 0, 'female': 1})

"""
Variables utilizadas en el dataset del Titanic:

* **Pclass**: Clase de pasajero (1ª, 2ª o 3ª clase).
* **Sex**: Sexo (Género del pasajero).
* **Age**: Edad.
* **SibSp**: Número de hermanos/cónyuges a bordo (*Sibling/Spouse*).
* **Parch**: Número de padres/hijos a bordo (*Parent/Children*).
* **Fare**: Tarifa (Precio del boleto).
"""

features = ['Pclass', 'Sex', 'Age', 'SibSp', 'Parch', 'Fare']
X = df[features]
y = df['Survived']

# 2. Configuración de la Validación Cruzada Estratificada
# Usamos 5 divisiones (folds)
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
modelo = RandomForestClassifier(n_estimators=100, random_state=42)

"""
Estas dos líneas de código son los cimientos de una evaluación robusta de tu modelo de aprendizaje automático. Aquí te detallo qué hace cada una:

1. skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
Esta instrucción configura la estrategia de Validación Cruzada Estratificada.

n_splits=5: Divide tus datos en 5 partes (o folds). En cada iteración, el modelo usará 4 partes para aprender y 1 parte para evaluarse a sí mismo. Esto se repite 5 veces hasta que todos los datos han servido como prueba al menos una vez.

Stratified (Estratificada): Es la parte más importante. Garantiza que la proporción de pasajeros que "Sobrevivieron" vs. "No Sobrevivieron" sea la misma en cada una de las 5 divisiones. Esto evita sesgos y asegura que el modelo vea ejemplos de ambas clases en cada iteración.

shuffle=True: Mezcla los datos de forma aleatoria antes de dividirlos. Esto es crucial para romper cualquier orden que el dataset pudiera traer (por ejemplo, si los datos estuvieran ordenados por fecha o apellido).

random_state=42: Fija una "semilla" para el generador de números aleatorios. Esto garantiza que cada vez que ejecutes el código, la división sea exactamente la misma, lo que permite que tus experimentos sean reproducibles.

2. modelo = RandomForestClassifier(n_estimators=100, random_state=42)
Esta instrucción crea la instancia del modelo que vas a entrenar.

RandomForestClassifier: Es un algoritmo de tipo "ensamble". En lugar de confiar en un solo árbol de decisión, crea un "bosque" de múltiples árboles y toma la decisión final combinando las respuestas de todos. Es muy potente porque corrige los errores que un solo árbol podría cometer.

n_estimators=100: Define que el "bosque" estará compuesto por 100 árboles de decisión individuales. A mayor número de árboles, mayor estabilidad, aunque aumenta el costo computacional.

random_state=42: Al igual que en la validación cruzada, esto asegura que el proceso interno de selección de muestras (para construir cada árbol) sea consistente. Si ejecutas el código mañana, los resultados serán idénticos.
"""


# 3. Realizar predicciones usando validación cruzada
# cross_val_predict devuelve las predicciones de cada punto cuando le tocó ser test
y_pred = cross_val_predict(modelo, X, y, cv=skf)

# 4. Evaluación
# Matriz de Confusión
cm = confusion_matrix(y, y_pred)
print("Matriz de Confusión:\n", cm)

# 

# Reporte detallado (Precisión y Recall)
print("\nReporte de Clasificación:\n")
print(classification_report(y, y_pred))

# Visualización de la Matriz de Confusión
plt.figure(figsize=(6, 4))
sns.heatmap(cm, annot=True, fmt='d', cmap='Greens', xticklabels=['No Sobrevió', 'Sobrevivió'], yticklabels=['No Sobrevió', 'Sobrevivió'])
plt.title("Matriz de Confusión - Titanic")
plt.ylabel("Real")
plt.xlabel("Predicho")
plt.show()

// END TITANIC CODE

### 3. Ajuste según el Objetivo de Negocio (Trade-off)

La aplicación de un modelo no termina en la precisión. Debes decidir qué prefieres según el contexto:

* 
**Maximizar Recall (Sensibilidad):** Si, como en el ejemplo de detección de fraude, es más caro "no detectar" un caso (Falso Negativo) que "falsificar una alarma" (Falso Positivo), debes ajustar el umbral de decisión del modelo.


* 
**Maximizar Precisión:** Si las falsas alarmas generan una mala experiencia de usuario (por ejemplo, bloquear una tarjeta legítima), prioriza la precisión.



### 4. Ciclo de Mejora Continua (Validación)

No confíes en una sola ejecución. Aplica siempre la **Validación Cruzada** que ya configuramos (`StratifiedKFold`) para asegurar que el modelo sea generalizable.

* Si notas que el rendimiento es muy diferente entre los 5 *folds*, tu modelo está sufriendo de **sobreajuste (overfitting)** y necesita simplificarse (por ejemplo, reducir el número de variables o ajustar la profundidad del bosque).

### 2. Credit Card Fraud Detection
https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud

Un dataset altamente **desbalanceado**.

* **El reto:** Identificar transacciones fraudulentas en una lista de transacciones normales.
* **Por qué practicar aquí:** Es el escenario ideal para el **Recall**. Tienes millones de transacciones normales y muy pocas fraudulentas. Si tu modelo dice que "todo es normal", tendrá una precisión alta pero un **Recall de 0%** para fraudes, lo cual es inútil. Aquí la **Validación Cruzada** es vital para asegurar que el modelo no se "aprenda" solo los ejemplos de fraude, sino que aprenda a generalizar el patrón.

Para abordar un dataset altamente desbalanceado como el de detección de fraude, debemos centrarnos en métricas que penalicen omitir fraudes reales. A continuación, presento la estructura profesional para implementar este modelo, integrando validación cruzada, SMOTE para equilibrar los datos y la persistencia necesaria para usarlo en producción.

### 1. Estrategia Técnica

Para este reto utilizaremos:

* 
**SMOTE (Synthetic Minority Over-sampling Technique):** Crea ejemplos sintéticos de la clase minoritaria (fraude) para equilibrar el entrenamiento.


* 
**Recall como métrica prioritaria:** En el sector bancario, un Falso Negativo (dejar pasar un fraude) es inaceptable, por lo que maximizar el Recall es la meta.


* 
**Validación Cruzada Estratificada:** Garantiza que cada *fold* contenga una proporción representativa de fraudes.



### 2. Implementación: Entrenamiento y Guardado 

```python
import pandas as pd
import joblib
import seaborn as sns
import matplotlib.pyplot as plt
from sklearn.model_selection import StratifiedKFold, cross_val_predict
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report, confusion_matrix
from imblearn.over_sampling import SMOTE

# 1. Carga
# Prueba idle
# df = pd.read_csv('creditcard_test.csv')
# Prueba Google Colab
df = pd.read_csv('creditcard.csv')
X = df.drop('Class', axis=1)
y = df['Class']

# 2. Balanceo con SMOTE
# Prueba credicard_test
# smote = SMOTE(k_neighbors=2, random_state=42)
# Prueba Google Colab
smote = SMOTE(random_state=42)
X_res, y_res = smote.fit_resample(X, y)

# 3. Entrenamiento del modelo final
modelo = RandomForestClassifier(n_estimators=100, random_state=42)
modelo.fit(X_res, y_res)

# 4. Guardado
joblib.dump(modelo, 'modelo_fraude.pkl')
joblib.dump(X.columns.tolist(), 'columnas_fraude.pkl')

# 5. Generación de Matriz de Confusión para reporte
y_pred = cross_val_predict(modelo, X_res, y_res, cv=5)
cm = confusion_matrix(y_res, y_pred)

plt.figure(figsize=(6, 4))
sns.heatmap(cm, annot=True, fmt='d', cmap='Reds')
plt.title("Matriz de Confusión - Detección de Fraude")
plt.savefig('matriz_fraude.png')

```
